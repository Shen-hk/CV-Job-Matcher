# TieLink 主 Agent 交互细节规格

> 讨论稿｜2026-11-24｜依据：[主 Agent 产品 PRD](AGENT_ORCHESTRATION_PRD.md)  
> 本文细化目标行为、状态与设计验收，不代表功能已实现。Figma 只使用 `9Wp2MFkHvQhRoWPA1IQ2RN`。

## 1. 贯穿所有流程的体验

用户始终与主 Agent 交流。团队、工具、文件和执行记录在当前任务中出现，复杂操作可以展开，完成后返回同一会话。

用户明确委托后可以离开聊天或切换应用，Agent 在支持的执行条件下继续推进，通过任务摘要与系统通知报告状态，结果可靠保存后回到原会话。完整执行与交付约束见 [后台委托与结果交付规格](AGENT_BACKGROUND_EXECUTION_SPEC.md)。

- 没有团队、没有资料也能发出第一条需求。主 Agent按需追问，不先要求配置成员。
- 创建或保存团队是配置行为，不自动启动业务任务。
- 直接查看 PDF、打开已有文档等单项动作可以直接调用工具。
- 对同一产物的连续修改保留任务与版本关系，不要求重新上传或新建目标。
- 不把停留在配置页、模型输出建议或工具调用开始当成操作完成。

## 2. 对话页面

### 2.1 信息层次

| 区域 | 内容与交互 |
| --- | --- |
| 顶部 | 主 Agent 名称、侧栏、任务入口、更多菜单；团队配置页面使用返回会话入口 |
| 当前任务摘要 | 展示当前任务与真实步骤；有其他会话任务时显示紧凑摘要，点击回到所属会话；多个事项可展开任务列表 |
| 用户消息 | 自然语言要求、附件引用、这次指定的团队；已发送消息可回看 |
| Agent 回复 | 必要解释、追问和结果摘要；对话身份保持为主 Agent |
| 操作卡片 | 资料选择、工具调用、执行摘要、产物预览、确认与恢复 |
| 固定输入栏 | 多行输入、附件、自动能力选择或指定团队、发送；流式回复可停止生成，运行任务在任务卡中暂停或取消 |

首次使用显示 Agent 问候与可发送的需求示例。用户开始任务后，示例不挤占消息流。回访优先恢复当前会话、草稿和实际执行状态。

### 2.2 输入与滚动

- Android 输入法回车默认换行，发送使用明确按钮；空白内容且没有可处理附件时禁用发送。
- 输入框随内容增高，到上限后内部滚动；键盘出现时保证输入栏和最近消息可见。
- 输入草稿和待发送附件按会话保存；进入团队、资料或预览界面返回后保留。
- 用户正在看旧消息时不强制跳到底部，新增消息提示可点击回到最新。
- 流式回复时提供“停止回复”，输入草稿仍可编辑；停止生成只终止本次文本回复，不隐式取消已接下的后台任务。任务卡提供独立的暂停与取消入口。
- 执行中输入栏保持可用。补充要求先显示为用户消息，并在卡片反馈“已应用于后续步骤”或“正在调整任务”；不能只有输入回显而没有处理结果。
- 非关键说明可用于尚未开始的步骤。改变输入、工具或交付物时生成新计划版本，在安全边界切换并重做受影响部分；只有歧义、额外影响或超出已有授权才需要用户决定。
- 首版应用内同一时间实际执行一项工具任务；连续委托持久化排队，聊天不进入队列。当前任务卡说明正在修改哪项任务，另有新意图则建立新任务，指代有歧义时简短询问。

## 3. 主 Agent 如何选择能力

| 情况 | 默认行为 | 用户可覆盖方式 |
| --- | --- | --- |
| 问答或解释 | 直接回答 | 继续追问或转为具体任务 |
| 明确的单项操作，例如查看 PDF | 调用对应工具 | 指定文件、取消或改为其他动作 |
| 简历等多步骤专业任务 | 选择已有专业团队 | 选择自己的团队，或要求只做其中一步 |
| 用户明确指定团队 | 使用所选版本和允许工具 | 本次换用其他团队或恢复自动选择 |
| 没有合适团队，但现有工具足够 | 主 Agent 直接组织任务 | 用户可另行要求保存这套工作方式 |
| 用户明确要求创建团队 | 生成配置草案 | 修改、保存或放弃；不自动执行业务 |
| 必要资料缺失 | 问一个可操作的问题 | 上传、选择已有资料或缩小任务范围 |
| 灵感明确交给 Agent | 将本轮目标收敛为可交付的第一稿，公开假设后直接开始 | 补充要求、调整交付物或暂停 |
| 只讨论或只记录灵感 | 在对话中讨论，或按明确范围保存记录 | 后续再明确委托执行 |
| 所需工具没有接入 | 说明能力缺口，提供可执行替代动作 | 选择替代动作或结束；不伪造外部结果 |

“自动选择能力”是默认模式。手动选择团队默认作用于下一条请求，正在执行的任务不受静默影响；用户可明确设为本会话默认。输入栏及任务详情显示实际采用的团队版本。

工具不可用时不偷偷扩大授权或换到能力更弱却继续显示成功。更换模型、工具或团队会影响任务结果时，在对话中说明。

## 4. 资料与附件

### 4.1 来源与状态

附件入口包含导入文件、选择已有资料、粘贴文本；类型支持范围以实现为准。目标状态为：未发送、解析中、可使用、解析失败、已移除。

- 导入并解析不自动新建团队。只有当前消息所引用的资料提供给任务。
- 已有资料选择页显示名称、类型、版本、更新时间及“本次使用”范围。
- 选择本次资料不等于永久授权所有团队；新任务显示实际引用，不能默认把所有简历和记忆塞入请求。
- 解析中禁用依赖该附件的执行；可以继续输入需求。失败展示原因、重选、重试或粘贴文本。
- 移除待发送附件只移除本次引用；删除资料本体需要在资料管理中明确操作。
- 简历和 JD 是当前任务输入，阅读整理任务只需要文本，不出现必填简历字段。

### 4.2 输入变更

运行引用具体资料版本。用户在另一页面修改了资料后，不把新内容自动塞进正在执行的旧步骤。恢复时说明输入已改变，用户选择保留原输入或暂停后采用新输入；后者重新验证受影响的产物和依赖。

## 5. 团队创建与客制化

### 5.1 普通用户优先看到的字段

| 字段 | 行为 |
| --- | --- |
| 名称与用途 | 一句话说明团队适合处理什么 |
| 角色 | 职责、输入与输出；允许增删和调整，不要求多个角色 |
| 工具范围 | 从已注册工具选择，说明其读取、生成、预览或保存能力 |
| 常用步骤 | 以列表表达顺序与依赖，调整时验证上游产物是否存在 |
| 输出偏好 | 例如一页简历、先给修改对照、不补写事实、保留原始版本 |

高级指令放在展开项。首版不默认展示模型参数、代码、节点画布或实现术语。

### 5.2 创建与保存

用户在聊天中描述想要的团队，Agent 输出配置草案并解释用途。用户可进入编辑，也可在聊天中说“去掉面试角色，只保留简历相关工具”。保存后回到原会话，明确配置已保存、业务任务尚未开始。

团队名称、角色职责、工具和输出偏好形成版本。编辑已被某个运行采用的配置，不改变旧运行；原运行继续绑定旧版本，除非用户明确暂停后切换。

### 5.3 依赖与无效配置

- 删除角色时检查下游输入；允许重新指派产物，不能留下无法解释的空步骤。
- 调整顺序不能把读取上游产物的步骤移到上游之前；用具体原因说明冲突。
- 禁用工具后检查输出约定。例如当前 PDF 流程依赖 HTML 版式，禁用 HTML 生成时提示恢复工具或改为仅输出文档。
- PDF 查看与 PDF 生成是不同能力，关闭查看不等于禁止生成，打开查看也不代表可以生成文件。
- 配置无效时允许继续编辑，阻止保存为可运行配置，并标记具体缺口。

## 6. 工具调用与产物

### 6.1 工具分类

| 能力 | 输出与边界 | 确认规则 |
| --- | --- | --- |
| 读取与解析 | 结构化内容或读取结果 | 使用当前已授权资料，不反复索取同一授权 |
| 分析与草稿生成 | 建议、文档草稿、HTML 等新产物，自动保存在任务空间 | 按用户明确任务推进；不覆盖原始资料 |
| 预览 | 打开已有文档、HTML 或 PDF | 查看不自动重新生成、不修改内容 |
| 采用、正式保存与覆盖 | 将指定版本存入正式资料，或变更既有资料 | 呈现具体对象与变更；已有授权在约定范围内有效 |
| 外部发送或提交 | 真实外部操作及凭据 | 首版未接入；不把建议文本当成已发送结果 |

卡片显示实际工具名、资料引用、状态及产物；模型写出“已保存”不能代替工具结果。

### 6.2 文档、HTML、PDF 的关系

文档内容是可编辑主体；HTML 是版式产物；PDF 是导出或阅读产物。它们需要分别记录版本和来源。

- 修改文档 v4 后形成 v5 草稿；基于 v4 的 HTML 和 PDF 保留，但标明版本，需要刷新时重新生成。
- “再改项目经历”默认指向当前选定的文档，而非所有历史版本；不明确时询问产物。
- 进入预览保留会话、任务和产物关联；返回聊天后主 Agent 引用刚才的内容继续处理。
- HTML 默认展示渲染结果，查看代码属于可选高级操作；不能把实现细节放在普通用户主流程中。
- PDF 支持页码、缩放、返回原会话；导出和系统分享由用户主动触发，不能自动对外发送。

### 6.3 审阅与保存

草稿、已采用、已保存到个人资料分开。受委托生成的草稿自动持久化在任务空间，切后台后不会因为未点保存而丢失；这不等于覆盖原始资料或设为当前正式简历。修改对照标明本次变更，采用或覆盖时显示具体版本，以及是否保留原文件。

用户明确要求“生成 PDF”时，可以基于本轮草稿生成新 PDF，无需一律先审阅文档；只有本次明确要求“先让我确认再导出”才等待。文件导出到公共位置、系统分享与采用为正式资料分别处理。任务空间的可靠保存属于后台交付的必要步骤。

用户拒绝保存时，保留草稿并回到对话，可继续编辑、预览或结束。依赖“已采用内容”的步骤等待决定；不因此冻结全部可执行操作。

保存成功必须来自实际工具结果；失败可重试，超时或未知结果先检查操作状态。恢复不能重复创建已保存版本。

## 7. 委托、后台执行、停止与恢复

### 7.1 接单与离开

接单回复用一两句话说明本次交付和默认假设，例如：“我先整理一页方案，包含使用流程和待验证问题。你可以去做别的事，做好后会在这里交给你。”只有运行请求和输入引用已经可靠保存后，才使用“已接下 / 已排队”。排队中的任务不能说成已经开始执行。

不要求普通用户理解“后台模式”或再点击“开始”。是否离开页面由用户决定，返回键、Home 键、切换应用和锁屏都不作为任务取消命令。缺少关键事实时说明具体缺口；非关键格式、名称、语气先采用合理默认并允许修改。

### 7.2 状态

| 状态 | 页面表现 | 可用动作 |
| --- | --- | --- |
| 已排队 | 任务已接下，显示前方任务数；不伪造运行步骤 | 调整要求、取消排队、优先处理 |
| 正在执行 | 当前动作与已完成步骤，按需展开交接 | 补充要求、暂停、取消、查看已有产物 |
| 等待网络或系统调度 | 已保存进展、等待原因和更新时间；停止显示活动动画 | 等待、暂停、查看成果 |
| 需要你补充 | 一个具体问题和已完成内容；释放执行位 | 回复、补资料、调整范围、稍后处理 |
| 等待确认 | 对象、具体影响和可审阅变更；释放执行位 | 确认、调整、拒绝、稍后处理 |
| 暂停中 / 已暂停 | 先显示正在等待当前操作安全结束，再显示可靠检查点 | 查看成果、恢复排队、取消任务 |
| 正在核对恢复状态 | 最近检查点、需要核验的操作，不显示虚构运行进度 | 查看详情、取消后续工作 |
| 部分完成 / 失败 | 分别列出已有交付物、缺失项和原因 | 重试未完成部分、换资料、调整或结束 |
| 已取消 | 已保留成果与未执行步骤，不继续自动运行 | 回看、以已有成果新建任务 |
| 已完成 | 约定交付物可打开、版本一致；未读标记独立显示 | 回看、继续修改、导出或新任务 |

进度来自结构化步骤事件，不由模型编造百分比。优先显示“正在生成版式 · 第 3/4 步”；数量变化时显示“计划已调整”。长时间无事件显示最近更新时间，超出工具超时后切换到核验、重试或失败，不让动画无限循环。待确认步骤不计为完成；存在失败依赖时不将下游标为成功。

### 7.3 系统通知

| 类型 | 示例文案 | 点击与操作 |
| --- | --- | --- |
| 运行中，静默更新 | “正在整理项目经历 · 第 2/4 步” | 查看进度、暂停；详情页可取消 |
| 运行中，已有阶段成果 | “正在生成 PDF；简历草稿已完成” | 展开查看成果摘要，点击“查看成果”打开已保存草稿；后台继续执行 |
| 排队 / 等待网络 | “任务已排队” / “等待网络，已保留草稿” | 查看任务；不持续反复响铃 |
| 需要用户 | “需要你补充目标岗位，简历已解析” | 直达对应问题；不默认在锁屏暴露简历信息 |
| 完成 | “结果已准备好，点击查看” | 直达原会话结果卡，或明确选择打开对应产物 |
| 部分失败 | “文档已生成，PDF 导出未完成” | 查看已有成果、重试导出 |

上表文案用于应用内或用户允许详情的通知；锁屏默认使用“任务正在处理 / 有任务需要你处理 / 结果已准备好”等通用文案。状态栏只依系统能力显示图标，不绘制跨应用悬浮窗，不将悬浮窗授权作为任务条件。

首次合适任务时请求通知权限，拒绝后显示一次非阻断说明：“任务会继续；可回到这里查看结果。”通知关闭时不无限重复请求。进度通知与需要处理、结果提醒可分别管理；勿扰和系统渠道设置由系统控制，不能承诺必响。

相同步骤更新同一通知；只在状态实质变化时更新，不把模型逐字输出变成大量通知。进入等待用户后不长期占用运行通知；需要处理提醒替代它。任务结束后解除运行通知，完成提醒是否保留遵循系统能力。

运行通知的收起态优先呈现当前动作和最近一项成果；展开态展示最多三项已保存成果，如“岗位要求已整理 / 简历草稿 v2 已完成 / PDF 正在生成”。阶段成果与未完成步骤使用不同状态标记，不把进行中的 PDF 算成已有成果。通知中展示简短摘要，文档全文、HTML 和 PDF 在应用内查看。

有成果时主操作为“查看成果”，暂无成果时为“查看进度”，保留“暂停”作为第二操作。点击通知正文进入原任务进度；点击查看成果定位具体版本，不重新生成、不自动采用、不暂停后台任务。预览页顶部保留当前执行状态，可返回原会话；修改阶段稿时生成新版本并校验受影响的后续步骤。

点击通知先读取当前状态：旧的“需补充”通知若已处理，则打开最新结果或进度，不重复弹出旧问题。划掉通知只影响展示。系统提供的“停止应用”与通知划除不同，需要在恢复时核验中断。

### 7.4 回到应用与多任务

- 在原会话：原任务卡更新为真实状态，新增交付消息只出现一次；输入草稿、阅读位置尽量保留。
- 在其他会话：顶部显示“有 1 项任务进行中”或“有 1 项需要处理”；不把其他任务内容插入当前聊天，不自动跳页。
- 从完成通知进入：恢复原会话并定位结果，返回键回到应用内合理层级；无需用户从长历史中寻找。
- 应用内“任务”页按进行中、需要处理、结果未读和历史筛选；同一任务只列一次，多种属性可组合显示。
- 用户可以继续讨论其他事情；新工具任务排队，“优先处理”在当前工具步骤安全结束后调序，不中断未知状态的写入。
- 等待用户或暂停的任务不占执行位。补充完成后按当前优先级重新排队，不抢占已开始的任务。

### 7.5 暂停、取消与调整

- 暂停保留运行及检查点，可恢复；取消结束本次运行，保留已生成产物，后续可基于它们新建任务。
- 不可即时中止的保存操作显示“正在完成当前保存，随后暂停”，核验后才显示已暂停；取消同样不能回滚已经发生的操作。
- “先不生成 PDF，只给文档”属于交付范围调整。更新计划和完成标准后保留历史变更，不能继续沿用旧范围标失败，也不能把范围缩小归因于工具成功。
- “突出项目经历”如果影响已经完成的内容步骤，先生成文档新版本，再使旧 HTML/PDF 标为需要更新；旧版本保留。
- 用户没有回应待处理问题时保持等待，不假设同意，不每隔几分钟重复催促；首版仅在进入该状态时提醒一次。

### 7.6 Android 生命周期

目标要求：在支持的设备与系统条件下，普通切应用、离开会话及锁屏后仍能推进已接下的有限任务；执行不由聊天 ViewModel 的存活决定。断网转等待，重新可执行后从检查点续作，避免重复交付。

系统回收或重启后先恢复持久状态并核验运行所有权；系统调度许可时恢复，条件不足显示等待或待恢复。强行停止后不承诺自动运行，下次主动打开时核验；断网则保留已有成果并等待需要的网络条件。关机期间执行不属于本轮需求。

已知成功的写操作使用执行记录恢复，结果未知则先核验。输入或团队版本已变化时先处理冲突。首版不把多任务并行、永久后台执行或跨设备接续作为承诺。

PDF 等工具需要分别验证后台能力；若仅支持前台，在接单时说明该步骤限制，内容和 HTML 可先完成。完整要求包含 PDF 时，未生成 PDF 不能把任务标为全部完成。普通“生成草稿后用户可选审阅”不属于等待用户；只有完成约定真的依赖用户决定时才等待。

## 8. 会话历史与个人记忆

- 侧栏提供新对话、最近会话、我的团队、工具与资料、记忆与偏好、设置。
- 会话历史关联任务与产物；选择历史恢复上下文和可靠状态，不自动重跑工具。
- 删除正在运行的会话时，明确提供“取消任务并删除会话”或“保留会话”；不能产生无归属的后台任务。删除团队不影响已接单运行绑定的配置快照。
- 新对话默认不携带另一会话的全部文件；可主动引用已有资料或产物。
- 个人偏好与任务材料分开，例如“简历保持一页”可在用户明确要求后记为偏好。
- 用户说“记住这个”时展示保存内容与适用范围；有歧义时询问，不静默存入敏感事实。
- 记忆可查看、修改或删除；撤回影响未来注入，不抹掉用户已经保存的文档。
- 删除会话时说明是否包含草稿及执行记录。单独保存的资料不因删除会话而被无声删除。

## 9. 无模型、离线与权限拒绝

- 尚未配置模型时说明需要设置才能进行 Agent 生成任务；已接入的本地文件查看仍可使用。
- 没有可用模型时，不用虚构的 Agent 回复代替真实结果；本地嵌入能力不等于通用对话生成。
- 文件或麦克风权限被拒绝时提供粘贴文本、选择已有资料等适用替代入口；不让用户陷入重复申请循环。
- 写入授权被拒绝时保留可审阅草稿，说明这次未保存，可继续修改。
- 外部工具未接入时说明当前支持的动作，不制造已经登录、投递或发送的记录。

## 10. 设计状态清单

| 分组 | 状态 |
| --- | --- |
| A · 主对话 | 首次使用、目标与附件就绪、缺资料追问、团队执行、草稿、继续修改、直接工具、不支持能力 |
| B · 团队与入口 | 侧栏历史、团队选择、团队库、自然语言创建、配置草案、角色编辑、工具配置、版本冲突、保存配置 |
| C · 资料与产物 | 附件入口、资料选择、解析中、解析失败、保存确认、保存成功、HTML 预览、PDF 预览 |
| D · 执行与记忆 | 执行详情、部分失败、恢复会话、停止任务、记忆偏好、无模型、拒绝保存 |
| E · 后台委托与交付 | 灵感接单、排队、后台运行通知、锁屏隐藏详情、拒绝通知权限、其他会话任务摘要、补充提醒、完成通知、结果未读、通知直达结果、暂停中、等待网络 |

这些状态组成可审阅的设计流程。静态原型用于验证入口、文案、控制点及返回路径，不代表模型、文件生成或后台恢复已经实现。

## 11. 首版验收场景

1. 没有团队的新用户直接发出需求，主 Agent 能回复、追问或调用已接入能力。
2. 附件解析失败后可以重选或粘贴文本，不丢输入草稿、不假装执行成功。
3. 简历团队使用用户选择的版本，实际产物交接可回看，待确认不计为完成。
4. 用户说“项目再具体一点”，基于当前草稿形成新版本；原资料及旧导出文件保留。
5. PDF 查看只读取已有 PDF，不新建团队或隐式生成新文件。
6. 保存团队后返回对话，业务没有自动开始；后续可主动调用所保存版本。
7. 禁用必要工具时指出具体依赖，无法运行的配置不能作为有效团队保存。
8. 执行期间修改团队，当前任务继续原版本或明确暂停切换，不静默变更。
9. 一个工具失败时保留已成功产物，重试从受影响步骤开始，不重复保存。
10. 退出回来正确恢复“待确认 / 已暂停 / 正在核对恢复状态”等状态，而非统一显示执行中。
11. 用户拒绝写操作，草稿仍可查看和修改，没有伪造保存成功。
12. 阅读任务在同一主 Agent 中直接使用文本能力，不要求岗位、简历或团队配置。
13. 进入文档、HTML 或 PDF 页面后返回原会话，继续处理正确版本。
14. 用户能查看和撤回已保存偏好；新对话不默认读取所有历史资料。
15. 明确委托一个不完整灵感时，Agent 按公开假设先生成有用草稿；“只讨论 / 只记录”不误启动。
16. 切应用及锁屏后，已支持工具继续推进，通知显示真实步骤；返回不重复派发。
17. 执行中仍可发送消息，补充正确应用到对应任务，新任务进入持久队列，闲聊不排队。
18. 需要资料或确认时保留成果、提醒一次并释放执行位；用户不回复不自动同意。
19. 关闭或划除通知不取消任务；拒绝权限后仍能从任务入口找到状态和未读结果。
20. 完成通知直达正确会话和可打开的结果；重复点击、事件重放和冷启动不重复交付。
21. 断网、系统回收、预算达到上限、部分失败和暂停都有真实状态，不无限显示执行中。
22. 请求 PDF 但只有 HTML 时显示缺失项；草稿持久化成功不等于已采用为正式简历。
23. 简历草稿已保存、PDF 尚在生成时，通知同时显示当前动作和已有草稿；可以打开正确草稿版本，PDF 任务继续执行。
24. 展开通知只显示真实阶段成果摘要，待完成项标识清晰；新成果更新原通知，不新增一串消息或提前发完成提醒。
