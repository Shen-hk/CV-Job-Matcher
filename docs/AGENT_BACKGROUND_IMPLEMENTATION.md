# 主 Agent 后台文档任务：实现进展

> 2026-11-25｜Android 后台文档任务与可复用团队配置  
> 产品依据：[PRD](AGENT_ORCHESTRATION_PRD.md)、[后台规格](AGENT_BACKGROUND_EXECUTION_SPEC.md)  
> 这是代码与验证记录。完整团队编排、后台 PDF 和所有设备上的运行可靠性不在本次完成范围。

## 已加入的链路

在主 Agent 对话中明确委托文档任务，例如：

> 帮我把面试复盘助手这个灵感整理成一页方案，我先去忙。

应用保存用户消息和所属会话，持久化接单后启动独立前台服务。普通聊天仍沿用现有管线；文档任务不会占住聊天的流式回复协程。其他文档任务进入同一持久队列，每次实际执行一项。

调用已配置的模型生成 Markdown 草稿，收到明确完成标记后保存为正式任务草稿，再按本次工具选择以固定、安全的渲染器生成 HTML。生成中的部分文字、已完成草稿与 HTML 分别保存；只有本次约定的交付物齐全才标完成。未选 HTML 的团队只要求完整文档，不虚报已生成 HTML。

通知安静更新当前动作和已保存阶段成果。生成期间每隔至少 5 秒展示一次已持久化文字的短预览，明确标为“生成中，尚未完成”；不把它计为完整草稿。草稿保存后优先展示已保存草稿的节选。展开通知可以看到摘要，点击进入对应任务详情；任务详情可查看文档、预览 HTML，以及通过系统文件选择器导出 Markdown 或 HTML。锁屏公开版本只显示通用状态。

聊天内保留任务引用卡片。用户停留或重新打开所属会话时，已完成任务会补回成果卡片，按任务 ID 去重。如果主聊天正在流式回复，成果卡片等到回复结束再补入，通知仍实时更新，避免分裂正文或留下未结束段落。插入时重新核对当前会话引用，防止切换会话与结果到达交错时串入其他聊天。通知可直接打开正确任务详情，再通过“回原对话”恢复所属会话。

## 输入、修改与恢复

- 讨论后台原理、只记录想法和创建团队配置不会启动文档执行。明确的简历/PDF 要求继续走既有工具；后台入口暂不把它们静默降为普通 HTML。
- 本轮只提供当前请求和明确引用的原稿，不注入全部会话资料与记忆。附件沿用当前消息已有的文本提取结果。
- 草稿完成后说“再简短一点”等修改要求，会建立关联修订任务，引用原稿并保留旧成果。
- 生成中补充要求时，保存新的完整要求，原子地使旧执行失效，再接续新的任务；旧模型回调不能覆盖新要求。调整前的记录仍可查看。
- 暂停保留可靠检查点；取消不删除已有成果；已调整的任务不会当作可恢复的旧任务重新执行。
- 流式中断、模型输出上限、空结果与显式错误都不计完成。未完成文字不直接拼接到重试输出。
- 草稿已保存但 HTML 未完成时，继续操作复用草稿，只补做版式。尚未形成完整草稿时，继续会重新生成完整内容。
- 进程被终止后，下次进入先将遗留运行核验为暂停，用户明确点击继续后重启。暂不自动重启未知请求，不注册开机保活。
- 网络或模型配置失败目前显示为“需要处理”，用户修复后手动继续；自动等待网络并恢复调度尚未接入。
- 每次执行限制为 10 分钟，超时暂停并保留已有记录。跨尝试累计预算、费用估计和复杂重试策略仍待实现。

## 可复用团队配置

聊天输入区提供可选的团队入口，默认仍由主 Agent 直接处理。用户可以手动创建、编辑、删除和选用团队，或者从“灵感整理”模板开始填写。保存、选用和编辑配置都不发起模型请求、不创建后台任务。未保存的编辑在离开时提示保留或放弃。

每个团队保存名称、用途、工作要求和工具选择；目前文档编写为必选，HTML 排版与预览为可选，最多保存 20 个团队。名称最多 32 字符，用途最多 160 字符，工作要求最多 4000 字符。配置保存在本地 Room。

用户明确委托文档任务后，任务保存接单时的团队快照。模型实际收到该用途和工作要求，本次明确要求优先于默认偏好。明确说“不要生成 HTML”或“导出 HTML”时覆盖默认交付选择，接单卡片说明实际格式；仅在材料中提到 HTML 不改变工具选择。任务快照保存生效后的工具选择，不改动可复用团队本身。未选择的 HTML 步骤不会执行。团队配置不增加外部操作权限，也不提供任意工具执行。

已接下的任务不会跟随配置编辑而变化；删除团队不会删除任务或成果。修改已有草稿、生成中补充要求，都继承原任务快照；输入区团队选择只影响新文档任务。任务详情可查看当时采用的要求与工具。

这是单个主 Agent 使用工作配置与已接入工具的第一阶段，并未实现多个角色之间的独立模型调度。通过聊天自然语言自动生成、保存或按名称匹配团队也尚未接入。

| 接入 | `AgentViewModel.kt`、`AgentChatScreen.kt`、`MainActivity.kt`、`NavGraph.kt` | 聊天接单、成果回流、通知权限与跳转 |

Room 从 v15 升至 v16 新增 `agent_background_tasks`，再从 v16 升至 v17 新增 `agent_teams` 与任务中的团队快照。15→16、16→17 都使用显式迁移，保留业务表；14→15 的既有升级链继续有效。原有 v16 任务默认仍交付文档和 HTML。任务绑定源会话、请求标识和执行代次；暂停、取消和调整后，旧代次无法提交结果。

前台服务仅用于这条用户发起的远程内容获取与本地文档导出链路，声明 `dataSync` 类型与相应权限，并处理 Android 15 的服务超时。依据：[服务类型](https://developer.android.com/develop/background-work/services/fgs/service-types)、[超时处理](https://developer.android.com/develop/background-work/services/fgs/timeout)。服务从前台委托派发，未假定后台任意启动都被系统允许。

流式传输同时修正了背压和异常收束：网络回调向有界通道写入时不会静默丢弃已收到的文本；响应体与通道在异常时关闭，缺少完成标记或输出被截断时返回明确错误。

## 仍需设备验证与后续接入

普通切后台、锁屏、通知权限拒绝、渠道关闭、通知冷/热启动、真实模型断网、系统回收、文件导出及迁移需要在设备上执行验收。本轮未使用用户 API Key 发起实际生成，也未用模拟内容替代真实 Android 执行结果。

当前 Android 代码尚未具备：多个角色独立执行的通用团队运行时、任意工具编排、后台简历与 PDF 全链路、自动联网恢复、跨设备运行，以及累计执行预算。HTML 原型继续作为完整产品交互的讨论依据，不能把原型可点击状态都计为 Android 已完成功能。
